# v0.3.0 — 睡眠修复与小时窗口同步

这次发版解决两个实际问题：睡眠深睡数据缺失，以及每次同步都要拉全天数据。

> 本版本是本项目自维护分支（[ai-dachui/mi-fitness-mcp-enhance](https://github.com/ai-dachui/mi-fitness-mcp-enhance)）的 0.3.0；升级与问题反馈请在本仓库进行。

## 本次亮点

- 睡眠分段按实测重映射，深睡数据恢复
- 新增按小时窗口增量同步，心率单趟请求量降到约 1/12
- 主睡眠评分可从日汇总补齐

## 新增

- 同步支持时间窗口：MCP `sync_data`、REST `POST /api/sync`、CLI `sync` 新增 `hours_back` / `start_time` / `end_time`。心率、压力、血氧、异常心跳、运动可只拉最近 N 小时；一次 2 小时心率同步约 60–120 条，而不是全天约 1440 条。
- 同步接口接受 ISO 8601 时间（如 `2026-11-06T09:00:00`），窗口参数不用先拆成日期。

## 改进

- 主睡眠评分从日汇总接口补齐，可取得 0–100 的评分；没有对应日汇总的记录（部分手机单段记录与小睡）仍可能为空。
- 睡眠分段状态码按实测重新映射：`1`/`2` = 深睡、`3` = 浅睡、`4` = REM、`5` = 清醒、`6` = 未分期（手机单段跟踪，按浅睡计入）。
- 窗口模式下步数、睡眠、体重等日聚合数据仍按整天抓取，保证汇总值与评分完整。
- Web 仪表盘总览与查询页按 API 实际字段渲染：活动消耗、距离、静息心率、睡眠、血氧、压力与睡眠分段均可正常显示。

## 修复

- 修复只传 epoch 窗口、不带日期参数时无法同步的问题。
- 修复窗口模式缺少 `timezone` 导入导致的同步启动异常。
- 修复查询端点传入 ISO 8601 时间后按字符串比较、漏掉开始日的问题；查询端点现在统一按日期查询。
- 修复同步窗口起止格式混用（一端日期、一端 ISO 时间）时结束时间被忽略或报错的问题。

## 升级注意

1. **睡眠分段映射变化（必读）**：旧映射 `4` = 清醒、`5` = REM；新映射 `4` = REM、`5` = 清醒。重新同步历史数据后，已有记录的 REM 与清醒时长会按新映射更新，睡眠分期统计与旧版本不再直接可比。
2. 升级后建议先对最近 7 天做一次睡眠同步：按主键 UPSERT 补齐深睡分段与睡眠评分，无需数据库迁移。
3. 无破坏性 API 变更；`hours_back` / `start_time` / `end_time` 均为可选参数。旧版本可继续读取同一个 SQLite 数据库。
